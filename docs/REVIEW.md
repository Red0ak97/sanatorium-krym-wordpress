## Исключено из поставки

- 17 растровых изображений темы, включая фотографии и герб; все фотографии плагина.
- Старый `.git` со своей историей, настройками, журналами и hooks. История не переносилась и не объявляется безопасной для публикации.
- `.DS_Store`, `__MACOSX`, AppleDouble и старые инструкции с локальными путями.
- Контактные телефоны, email и адрес в подвале; реальные ссылки оформления заявки.
- Google Fonts: CSS использует системные шрифты без внешней загрузки.

Для публикации создан новый `.git`: история начинается с очищенной портфолио-копии. Старые коммиты не переносились. В архив поставки `.git` не включён. Оригинальные архивы и рабочий сайт не изменялись.

## Изменения публичной версии

- Тема ссылается на самостоятельно созданную SVG-заглушку вместо фотографий и герба. Слайдер сохранён, но его слайды показывают одну заглушку.
- Плагин проверяет наличие каждой фотографии и обложки. Отсутствующие фотографии пропускаются; для пустой галереи используется SVG, поэтому массив для просмотра не пустой.
- Сохранены пути `assets/css/room-photos.css` и `assets/js/room-photos.js`, необходимые для `filemtime()`.
- Удалены начальные пустые строки перед PHP, в частности в `functions.php`, где ранний вывод мог мешать заголовкам ответа и перенаправлению.
- В `functions.php` добавлена проверка `ABSPATH`.
- Добавлены корневые README и `.gitignore`; полный WordPress, база и uploads в репозиторий не входят.

## Выполненные проверки

- Проверены имена всех ZIP-записей: нет абсолютных путей, переходов `..` и символических ссылок. Извлекались только PHP/CSS/JS по разрешённому набору расширений; содержимое `.git` не запускалось.
- Просмотрены PHP и JavaScript: не обнаружены явные вредоносные вставки, обфускация, исполнение команд или встроенные учётные данные. Дополнительно выполнен поиск характерных функций исполнения, ключей и присваиваний паролей в текстовых исходниках темы.
- В сохранении объявления присутствуют проверка `edit_pages`, nonce, очистка входного текста и экранирование вывода. Плагин галереи формирует данные из фиксированного списка категорий, а JS использует DOM API и `textContent`.
- Все 9 PHP-файлов прошли `php -n -l` на PHP 8.2.29; все 4 JS-файла — `node --check`.
- Все ссылки `url(...)` в CSS разрешаются в существующие локальные файлы.
- PHP плагина выполнен в изолированной проверке с подставленными функциями WordPress: шесть категорий, непустые галереи, существующие ресурсы, отсутствие предупреждений. Проверены пустой каталог изображений и частичный набор локальных файлов. Это проверка формирования данных, а не интеграционный тест WordPress.
- В подготовленных PHP/CSS/JS отсутствуют внешние HTTP(S)-адреса, `mailto:` и `tel:`; по использованным шаблонам ключи доступа не найдены.

Статический просмотр и поиск по шаблонам не гарантируют отсутствие всех уязвимостей. Этот отчёт относится только к поставляемым исходникам, а не к рабочему серверу, WordPress core или другим плагинам.

## Что ещё не проверено

- Установка и работа в полноценном WordPress с базой данных.
- Визуальный вид на мобильных устройствах, работа клавиатуры и скринридера, все состояния слайдера и диалога.
- Поведение административного объявления под разными ролями и при некорректном nonce в реальном WordPress.
- Поддержка старых браузеров: JS содержит запасной способ открытия `dialog`, но закрытие всё ещё использует `dialog.close()`; старые браузеры без этого API не считаются поддержанными.
- Совместимость с другими плагинами и версиями PHP/WordPress.

В исходном `index.php` находится минимальная проверочная страница; полноценные шаблоны блога/архивов не добавлялись. Страницы, PDF, тексты из базы и дополнительные плагины рабочего сайта не восстановлены. Демонстрация потребует создания страниц по README.
